# 自动说书人与房间运行约定

## 范围与标准

当前范围为 5–12 人暗流涌动。5–6 人使用官方 Teensyville：邪恶互不获知队友，恶魔没有三个安全伪装。7 人起提供正常邪恶队友信息与三个未在场善良角色伪装。身份分配保持人数表与男爵修正；镇民不少于三人时兼顾首夜线索和主动能力。

参考：[基础状态](https://wiki.bloodontheclocktower.com/States)、[暗流涌动](https://wiki.bloodontheclocktower.com/Trouble_Brewing)、[Teensyville](https://wiki.bloodontheclocktower.com/Teensyville)。没有加入其他剧本或旅行者。

### 人数与玩法边界

5 人基础配置为 3 镇民、0 外来者、1 爪牙、1 恶魔；6 人为 3 镇民、1 外来者、1 爪牙、1 恶魔。男爵仍正常应用 +2 外来者、−2 镇民。Teensyville 在这里表示这些小局的开局信息规则，并不是另一套自动挑选的小剧本；22 个暗流涌动角色仍在可选角色池中。7–12 人按标准人数表配置。

当前没有 13–15 人房间、旅行者、传奇角色、自定义剧本、跨剧本相克规则或真人说书人任意改判界面。自动说书人只根据权威游戏状态和公开提名历史选择合法裁量，不读取耳语正文、语音、玩家表情或身份推理。合法选项中的策略选择不等于具备真人说书人的现场判断，也未宣称所有可能的角色组合已经穷尽验证。

## 权威夜序

首夜：投毒者 → 洗衣妇 → 图书管理员 → 调查员 → 厨师 → 共情者 → 占卜师 → 管家 → 间谍。

其他夜：投毒者 → 僧侣 → 小恶魔 → 守鸦人 → 送葬者 → 共情者 → 占卜师 → 管家 → 间谍。

客户端可提前提交合法目标；权威裁定按上述顺序执行。被杀的信息角色不再收到后续信息。守鸦人的私密选择完成前，公开座位与人数仍显示入夜前状态，黎明只公布死亡名单与结果，不公布原因或身份。

死亡以死亡前人数判断猩红女郎，符合条件的猩红女郎优先于小恶魔自杀传位。毒效在黄昏、来源死亡或来源变为其他角色时结束。送葬者和圣徒区分处决事件与处决致死。

参考：[猩红女郎](https://wiki.bloodontheclocktower.com/Scarlet_Woman)、[小恶魔](https://wiki.bloodontheclocktower.com/Imp)、[送葬者](https://wiki.bloodontheclocktower.com/Undertaker)。

## 说书裁量

- 醉毒信息从完整合法信息集合选择，真值仍是候选；参考近期输出与存活人数。
- 隐士、间谍按当前能力的查验范围和当时醉毒状态登记；死亡不取消这两个角色明确保留的登记能力。
- 首夜信息随机选择合法目标及干扰者，再随机展示两人的顺序。酒鬼按实际外来者身份登记。
- 镇长允许原目标、其他活人、死者及恶魔成为合法结果；自刀继任者结合公开提名历史与既往裁量加权。
- 间谍魔典包括身份、生死、醉毒、保护、红鲱鱼、已用能力和首夜线索提醒。
- 随机种子仅存在服务端私密状态。公开 gameId 与房间身份种子独立，防止公开 ID 推导隐藏身份。
- 裁量记录仅在终局 privateView.storytellerDecisions 交给参局玩家，公开演出事件绝不包含私密理由。

参考：[间谍](https://wiki.bloodontheclocktower.com/Spy)、[隐士](https://wiki.bloodontheclocktower.com/Recluse)、[醉毒状态](https://wiki.bloodontheclocktower.com/States)。策略是可解释的确定性加权策略，不是读取玩家语音或通用大模型判断。

## 产品交互约定

所有活玩家可以公开宣称猎魔人，每天最多一次；只有真实、健康、未用能力的活猎魔人可能产生死亡。所有角色共有的枪击动画不证明角色。真实猎魔人能力仍是整局一次，醉毒时使用也会消耗。可以选择自己或死者。

20 秒辩护、每席 1.5 秒计票、每日一次假称猎魔人和全体活人确认结束白天，是本产品的节奏与操作约定。它们不应被角色卡文案描述为实体游戏强制时限。无法完成当前操作时使用统一等待提示与恢复入口；服务端不会用超时随机选人来代替玩家的隐藏决定。

自提名、提名死者均合法；死者不能提名。撤回已公开提名仍消耗双方当日次数。投票等待有表决资格者，耗尽鬼票者不阻塞；死管家不受生前主人限制。公开有效票数与最终计票使用同一份冻结的计票记录。

生产环境提名后有 20 秒辩护，被提名者可以主动提前结束；随后从被提名者下一座起顺时针每席 1.5 秒计票，被提名者最后计票，耗尽鬼票的死者自动跳过。玩家可以提前举手或放下，到本席截止时锁票。没有手势的玩家视为不举手，不消耗鬼票。

所有有投票资格者的举手均计票。管家须在自己被计票时自觉遵守主人举手或已计赞成的限制；误投仍计票，只向本人提醒，避免公开计票差异泄露身份。健康与中毒显示相同私密提醒。鬼票在计入时即时消耗。掉线、无人提交也按时完成整轮。枪击演出会暂停并顺延剩余计票时间。白天结束仍需所有活玩家确认。

仅规则单测的 presentation:false 模式取消辩护和计票等待，允许全员提交后立即结算；真实生产时钟机制由 clockwise-voting.test.ts 独立验证。

## 公开演出契约

ExperienceEvent 有稳定 id、seq、gameId、kind、startsAt、durationMs 与只含公开信息的对象座位。完整历史可供重连追赶，不再只保留最后八条。

网络视图只读取已提交的 publicProjection。startsAt 前不发送未来事件；准备包为中性文案。结果点由事件timingVersion决定；v1的SHOT/EXECUTION为2800ms、DAWN/GAME_OVER为2100ms，v2为3600/2800ms；v3的SHOT850ms、EXECUTION1000ms、DAWN1400ms、GAME_OVER900ms。终局结束时才公布全员身份与裁量记录。500ms 时钟在下一次 tick 原子发布到期节点并增加 revision；GET、私密视图、WebSocket、重试与大屏共用投影。内部提前计算的终局、能力、上下文和未来排队事件不能泄露结果；跳过动画不会提前公开。

新局presentationVersion=3：枪击2600ms、处决2800ms、黎明4200ms、入夜3600ms、终局5200ms，阻塞事件lead为250ms。提名800ms/票结果1200ms仅为非模态展示，startsAt=occurredAt、不写演出锁、不延迟下一合法动作；其发布节点只更新event，同提交同步最新业务状态，不能回写旧phase/context/nomination/举手。枪击仍暂停计票并顺延剩余辩护/席位时间。旧局和历史保留v1/v2原时序及1500ms lead，不原地改写。NOTICE按当前阻塞队列排程；阻塞演出结束前服务端拒绝新游戏操作，客户端必须按serverNow对时。

投毒、保护、查验使用行动者自己的 ACTION 历史，effect 分别为 POISON / PROTECT / DIVINATION，targetSeats 只进入该玩家私密视图。

## 房间与恢复接口

- GET /api/account返回本人本游戏资料及默认值；POST /api/account/profile仅可信登录账号可写nickname/avatar和expectedRevision，不能指定他人账号。恢复默认提交两字段null；头像仅允许已有Fribench目录URL。相同目标值重试不重复推进资料版本，不同值旧版本返回409。
- 资料在既有runtime队列中与房间快照原子提交；大厅、教学及进行中局即时同步本游戏显示，已保存战报/魔典快照不回写。资料更新不改变座位、秘密身份或准备周期。重连保留当前头像，明确修改资料时才更新。
- 活动PLAYER头像按稳定目录ID在房内判重（兼容v1/v2/v3）；随机真人/人机分配排除占用，显式冲突返回AVATAR_TAKEN且不发生部分加入/人机替换/资料版本变动。本席精确当前URL与既存重复可保留；旧pending头像冲突时保留当前头像并清pending。summary公开roomInstanceId/state/canJoin及occupiedAvatars，不附昵称、席位身份或凭据。

- startTutorial 仅大厅、人数齐备且全员 ready/30秒内在线；可跳过教学但不能跳过身份确认。reset 仅接受正常终局演出完成或 ABORTED；RUNNING 必须先由现任房主明确中止。
- setReady(code, token, ready)：大厅准备；reorderSeats 仅房主可用；阵容或座序变动清空准备并轮换 setupId。公共大屏只读。
- privateView.participant.tutorialComplete：只向本人返回教学完成状态；刷新后已完成者继续等候其他玩家，不必重复教学。
- pulse(code, token, now?)：更新在线心跳，30 秒无心跳标记离线。
- advanceTime(now?)：返回发生变化的房间 code 列表，供持久化和广播。夜间/身份确认超时只公开统一等待提示，不代替玩家选目标，也不点名隐藏行动者。
- resume(code, token)：仅能清除已存在的等待提示并给暂停阶段新的截止时间，不能延长正常表决。
- finishDefense(code, token)：只有被提名者可以在辩护窗口内提前进入顺时针计票。
- rotateParticipantToken(code, oldToken)：发新凭证，旧凭证立刻失效。
- listCodes()、snapshot(code)、restore(snapshots)：供应用持久化。restore 保留运行中的绝对截止时间与夜序位置。
- 取消教学、移除玩家、离线5分钟接任、中止及返回大厅在所有玩家阶段都有“更多”入口；中止不判胜负、不追加身份。
- 命令绑定独立房间实例、准备周期及本人命令版本；投票绑定 gameId+ballotId。迟到请求拒绝且不消耗鬼票；重试同ID返回当前视图。
- GAME_OVER/ABORTED 可离房，终局座位与历史保持不变；重置后才清理离开玩家和重新编号。
- start 默认 SKIP、可选 OPTIONAL 三卡教学；markHostReady 只准备房主本人。玩家逐人完成/跳过教学，全部完成后才进入身份确认。房主不能代其他人准备或确认身份。
- reopen 原子完成撤销教学或中止并返回大厅；正常终局须等待身份发布。保留成员、座序、头像与单调递增命令版本，清空准备，轮换 setupId；新 gameId 在真正开始下一局时生成。
- lastResult 只在正常终局身份发布后生成，保留最近一次公开战报；reset/中止不覆盖。GET /result 只允许当前有效成员，匿名、移除和撤销凭据均不能读取，普通公共 GET 不附带战报。
- 同 Cookie/账号加入复用原座位；10分钟签名加入票据在首个响应丢失时恢复原成员，不重复占座。换设备、离开和移除撤销旧票据；玩家和大屏互不覆盖。
- 日落同意可撤回；新提名、射击和投票结果清空同意，进入夜晚后旧撤回拒绝。举手、锁票、鬼票消耗和同意数即时同步；死亡与身份仍按公开节点发布。

醉毒间谍从完整真魔典与完整扰动候选中确定性选择，每夜固定一次。扰动只交换相同生死的善良身份包和对应提醒，冻结本人、邪恶角色及死亡旧小恶魔；保留真实角色多重集合，禁止假候选直接标出间谍自身中毒，无合法扰动时使用完整真候选。

当前HTTP/WS协议5，旧协议4及更早HTTP请求426、旧WS1008要求刷新；快照schemaVersion=4，旧库在监听前、单写锁内先全量预检再单事务迁移；未知版本或不可还原快照拒绝启动。v1投票保留绝对时间、已冻结票和已耗鬼票，不追溯改票。普通回执只保存指纹与小结果，保留256条；淘汰后的旧请求仍因成员命令版本过期被拒绝。

- POST /api/rooms/:code/bots/command 沿用现任房主CONTROL授权、game/context/ballot版本、命令ID与队列事务；END_DAY仅让可结束白天的机器人同意，真人不变。NOMINATE_ONCE/SHOOT_ONCE各选一名公开有资格的机器人执行一次正常命令；射击包含VOTING，不按真实角色选执行者。无资格/非法目标明确409；重试回原回执及最新视图。反馈仅公开执行者、数量与提交结果，不提前公开死亡/隐藏身份。
- 新洗衣妇、图书管理员及调查员二选一线索在本人历史保存candidateGroup（ONE_OF、shown角色名与实际告知的两席）；醉毒使用实际误信息，不增强为后台真值。旧文本不解析补标记，公共视图不包含该字段。

- POST /api/rooms/:source/switch-ticket只允许当前PLAYER房主及匹配账号/来源实例，签5分钟HMAC能力票，绑定目标实例、源房主ID/凭据散列与当时账号；不写座位。目标join接受switchTicket，原Cookie/账号席位/已用票/新入座成功均统一finalize，在同一runtime/repository事务加入目标并关闭来源。用户明确关闭允许来源进行中或有其他真人；目标失败/持久化失败两房保持。来源Cookie用源路径清，目标Cookie用目标路径设。
- joinTransfers只在目标私密metadata保存散列和恢复信息，保留24小时、最多256条，仅清已到期，满额429不驱逐有效回执。新游客由原签名joinTicket恢复；已有游客须目标原Cookie；账号须同可信sub与当前确定性凭据。已提交重放允许票据过期但仍校验签名/实例/账号/当前凭据，不再入座、同步资料或关房。改原资料409、撤销凭据403；来源已结束SOURCE_ROOM_GONE，房主转移HOST_CHANGED，实例变化ROOM_INSTANCE_CHANGED。关闭后的客户端按404/WS失效回到首页，不清其他房间或全局资料。

## 验证
