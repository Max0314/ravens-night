## 实际运行与持久化

HTTP 与 WebSocket 使用同一个 `LiveRoomRuntime → RoomService` 路径。命令先在副本执行，数据库事务成功后才替换内存状态和广播。已有命令回执会校验当前凭据；返回当前视图，避免重试把 UI 倒退到旧状态。普通心跳更新在线时间，不为每次轮询写整份日志。

PostgreSQL 保存 AES-256-GCM 加密房间快照、最近 500 个修订范围内的快照日志，以及不含秘密的公开事件。旧明文快照可读取，下一次有效写入后转为加密。必须保持 `DATA_ENCRYPTION_KEY` 稳定并备份，否则加密快照无法恢复。

数据库 advisory lock 限定单个应用写入者，当前不是多实例分布式服务。持锁连接或连接池发生异常后拒绝继续写入，API 返回 503；已确认的状态仍可读取。运维恢复数据库后需重启应用，重新获得锁并载入已提交快照。不要仅重建连接后继续使用旧内存状态。

生产要求有效 `SESSION_SECRET`，启用数据库时还要求 `DATA_ENCRYPTION_KEY`。请求校验、登录/加入/恢复限流和 WebSocket Origin 校验均进入真实接口。错误响应不暴露数据库内部信息。
