# 鸦钟夜话：规则、房间与全局演出改造

本次从用户确认的审查方案开始实现，保留入口封面原画和文案。三名角色各四版的样张独立放在 `artifacts/character-directions-2026-09-27/`，用于选择美术方向，不会自动替换全角色立绘。本文件记录实际已接入的运行路径和验证范围。

## 实现内容

- 暗流涌动 22 个角色：按夜序执行能力，修正猩红女郎 5→4 人继任、恶魔自刀优先级、醉毒与登记、酒鬼外来者身份、死者能力、鬼票、处决与死亡的区别。详细规则和产品约定见 [RULES.md](../apps/server/src/rooms/RULES.md)。5–6 人采用标准 Teensyville 开局信息。
- 自动说书：醉毒结果包含合法真值，按历史输出和存活人数调整权重；首夜二选一打乱目标及呈现顺序；镇长改刀、恶魔传位在合法候选中裁量。私密裁量记录在终局开放复盘。这是可解释的规则与加权策略，不是读取语音或耳语的大模型裁判。
- 全局演出：服务端发出带 gameId、事件 ID、顺序、统一开始时间和时长的公开事件，玩家及大屏按服务端时钟播放；覆盖枪击、提名、投票结果、处决、黎明、入夜、终局。枪击含燧发枪入场、击发、烟雾、目标印章变化及合成音效；区分击毙与无人死亡。死亡不会公开身份。
- 表决：20 秒辩护，可由被提名者提前结束；从被提名者下一座起，每席 1.5 秒顺时针计票。允许提前举手，本席计票后锁定。管家按计票当刻主人状态裁定，鬼票在计入时消耗。枪击演出暂停并顺延正在进行的计票。
- 私密行动：下毒、守护、查验只在操作者设备显示私密回执。默认静音，避免同地游玩时因设备声音泄露角色。迟到回执不会打断全员公共演出。
- 手机与大屏：全部玩法模式都有完整个人城镇、公开历史、行动入口和死亡后的鬼票提示。大屏可选；隐私遮罩覆盖身份、线索和私聊。支持演出跳过、关闭音效和减少动态效果。
- 房间：全员准备、房主手机换座、教程完成后刷新恢复、房主继任、终局退出和重开；玩家与大屏使用独立且按房间限定路径的 Cookie。房间记录不存凭据明文。
- 耳语：邀请、接受/拒绝、两人私聊和返回广场。权限绑定参与者 ID，换座不会把聊天交给新座位的玩家。夜间不能发送耳语；仍保留外部语音入口，没有自建语音/视频系统。
- 换设备：10 分钟一次性恢复码，恢复时轮换凭据、旧设备失效。恢复请求的相同操作 ID 可以在响应丢失后安全重试；新生成恢复码会撤销旧恢复回执。

## 实际运行与持久化

HTTP 与 WebSocket 使用同一个 `LiveRoomRuntime → RoomService` 路径。命令先在副本执行，数据库事务成功后才替换内存状态和广播。已有命令回执会校验当前凭据；返回当前视图，避免重试把 UI 倒退到旧状态。普通心跳更新在线时间，不为每次轮询写整份日志。

PostgreSQL 保存 AES-256-GCM 加密房间快照、最近 500 个修订范围内的快照日志，以及不含秘密的公开事件。旧明文快照可读取，下一次有效写入后转为加密。必须保持 `DATA_ENCRYPTION_KEY` 稳定并备份，否则加密快照无法恢复。

数据库 advisory lock 限定单个应用写入者，当前不是多实例分布式服务。持锁连接或连接池发生异常后拒绝继续写入，API 返回 503；已确认的状态仍可读取。运维恢复数据库后需重启应用，重新获得锁并载入已提交快照。不要仅重建连接后继续使用旧内存状态。

生产要求有效 `SESSION_SECRET`，启用数据库时还要求 `DATA_ENCRYPTION_KEY`。请求校验、登录/加入/恢复限流和 WebSocket Origin 校验均进入真实接口。错误响应不暴露数据库内部信息。
