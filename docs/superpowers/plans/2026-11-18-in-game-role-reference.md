# 局内角色速查卡实施方案

游玩时，点「城镇」右边的「角色表」即可打开速查卡。卡片按四类连续列出 22 个角色，每行显示原创图标、名称和公开能力。读完可以直接关掉，点某一行则能看该角色的规则细节和原有立绘。

方案基线为 `4c651872f949e5e2a1f2ac0b17a43cab40f384f9`。本次核对的 Fribench ops GitHub main 为 `72f3c82320ee35951a088292f0aac38ca35417bc`。本文交付范围为交互、图标与实施契约。

## 1. 入口和阅读布局

- 竖屏游戏导航排列为「城镇｜角色表｜记录」，三个控件等宽。城镇和记录继续切换现有内容，原待办和未读标记各在原按钮内。「角色表」是展开阅读层的按钮，使用 `aria-haspopup="dialog"` 和 `aria-expanded`，不占用 `TOWN`、`RECORD` 的页面选中状态。从记录打开时，关闭后回到记录原位置。
- 只在显示三入口的 `.game-tabs` 上启用三列样式。矮横屏沿用 104px 左侧栏和纵向顺序，按钮间距为 0。角色表最小 44×44 CSS px，城镇和记录沿用矮屏最小 32px 高，给现有操作栏和右侧圆桌留出空间。
- 入口出现在玩家端已进入正常城镇导航的实时对局，覆盖首夜、讨论、提名、投票及后续夜晚。身份揭晓阶段、等待有效玩家快照、局已中止或已进入结算页时不渲染入口。同步中、已有需先处理的弹层、私密演出或全屏公开演出正在播放时暂不可打开。已有普通读物、首页、开局教学、大厅、独立图鉴、大屏及房间菜单维持原入口。
- 列表页头固定显示「角色表」和「关闭角色表」。下方单一滚动区先放四个可点的分类跳转，再依次放镇民 13、外来者 4、爪牙 4、恶魔 1。点分类跳到同一滚动区内对应标题，所有分组始终在同一张卡内。按角色目录中的组内顺序排版。每个角色占一整行，左侧 32px 图标，右侧角色名与可自然换行的能力摘要。最小行高 48px，摘要 14px、行高约 1.5，禁止截断能力文字。
- 竖屏卡片左右各留 12px 和安全区，宽屏最大宽 680px，内容纵向滚动。外层使用现有视口变量和安全区边距，正文区采用 `min-height:0` 和 `overflow-y:auto`。330px 以下仍保持单列和完整换行。页头及关闭按钮始终可见，分类跳转随正文滚动。无需横向手势、卷页动画、画布截图或每个角色先打开详情。
- 点行后在同一张卡内展示详情。页头保留「返回角色表」和「关闭角色表」，正文顺序为角色名与分类、能力、规则细节、原有无框立绘。摘要原文位于首屏，立绘在下方按现有 `roleArt` 路径加载。缺少规则细节时只显示公开摘要。完整手册继续提供游玩建议和示例。详情返回恢复所点角色与列表位置。关闭按钮从任一层直接退出整张卡。

## 2. 代码职责与数据契约

| 模块 | 输入与职责 | 输出及边界 |
| --- | --- | --- |
| `PlayerGame.tsx` | 游戏分区导航增加 `onOpenRoleReference?: (trigger: HTMLButtonElement) => void` 入口。仅生产 App 接线后显示按钮。用现有 `privateVisible`、身份阶段、同步/演出状态和弹层占用判定可用性。已有手册、选人轮盘、私聊、身份窥视、表决或其他确认层在最前面时，略过新打开请求 | 只发出打开请求。继续由原组件拥有 `TOWN/RECORD`、选人、私聊草稿、记录位置、投票和处理待办的状态 |
| `App.tsx` | 现有 `guide` 在三种 `GuideMode` 之外增加 `{kind: 'role-reference', scope: string}` 请求。接收入口按钮引用，记在 ref，选择当前阅读层 | 同一时刻只渲染现有手册或 `RoleReferenceOverlay`。`GuideMode` 与传给 `GuideOverlay` 的类型维持原三种值，已有入口继续调用原 `onOpenGuide` |
| `guide-priority.tsx` | `mode` 允许接收已通过作用域验证的 `'role-reference'`。复用当前局的 `EXECUTION`、`GAME_OVER` 判定、时间与完成信号 | 提供原有 `suspended`、`criticalActive`。速查卡挂起后的返回按钮用「返回角色表」，退出按钮在终局用「查看结算」，其余用「继续城镇」 |
| 新增 `components/RoleReferenceOverlay.tsx` 与同名样式文件 | props 为 `suspended: boolean`、`onClose: () => void`，从公开角色目录和美术映射查询内容。此处 `onClose` 只负责用户主动关闭。掌管列表/详情、滚动、分类跳转与焦点 | 渲染一个带标题的 `role="dialog"` 及一个滚动区。外部投票和待办控件可交互，所以省略 `aria-modal`，用 `inert` 隔离底层游戏操作 |
| 新增 `role-icons.ts` 与 `public/assets/ravens/role-icons-v1/` | 用公开 `roleId` 查对应的版本化图标 URL。布局和占位由前端控制 | 已知 ID 对应唯一图片。未知或加载失败使用统一中性占位，名称及能力仍显示 |
| 现有 `@ravens/content`、`guide-content.ts`、`role-art.ts` | 用 `beginnerRoles` 的 `id/name/type/summary` 构成列表。用 `roleTypeNames` 取分类名，用 `rolePlayGuides[roleId].mechanics` 查详细规则 | 角色名、能力和立绘共享当前唯一公开来源。速查详情使用已有 `RolePortrait` 和响应式立绘地址，保留立绘加载失败时的现有组件行为 |

列表可用一个模块级有序分组，角色身份 ID 直接用目录字符串。设分类顺序为 `TOWNSFOLK, OUTSIDER, MINION, DEMON`。详情状态只保存 `selectedRoleId?: string`。选择前验证 ID 存在于公开目录，非法 ID 保持列表。图标映射不依赖真实身份 ID、席位或房间选角结果。

打开请求的作用域使用 `JSON.stringify([snapshot.generation, roomInstanceId, gameIdOrSetupId, participantId])`。优先从当前公共房间快照取房间实例和游戏 ID，必要时用已接收的同一会话私密快照补缺，旧视图可退到房间码与 `setupId`。正常局内重连时，公共快照仍足以识别同局，私密快照短暂缺失不会清除可识别的同局卡片。在渲染派生 `activeGuide` 时校验当前屏幕、作用域和 `ABORTED`，过期请求不挂载，同时清理请求与触发点引用。原有随房间及游戏切换清手册的 effect 只负责原三种手册请求，速查卡由上述作用域收口，避免私密快照单独刷新误关。把同一已校验的状态用于阅读层、通知和焦点逻辑。`GuidePriorityBoundary` 的实例要在同局公开和私密快照替换时稳定，按现有对局边界计算其 key，并用上面的公开 `gameId` 优先级、`setupId` 后备和会话代数补全。速查请求存在期间，普通手册打开回调直接返回。先处理返回条或关闭，再允许打开旧手册，避免新手册继承 `stowed`。

## 3. 行为、并发与失败路径

| 触发 | 前端处理与结果 |
| --- | --- |
| 第一次打开 | 在触发时记录按钮和当前作用域，列表从顶部开始，焦点落到标题。底层城镇或记录 DOM 保持挂载。打开动作只改内存状态。重复点击已打开的入口保持当前层和滚动位置 |
| 分类跳转 | 找到相应标题，在列表滚动区内即时滚到标题位置，再对标题 `focus({preventScroll:true})`。详情和挂起期间停用分类操作 |
| 点角色行与返回 | 进入详情前保存当前列表 `scrollTop` 与来源角色 ID，详情正文从顶部开始。返回后先恢复滚动，再把焦点还给对应行。若期间旋转屏幕或放大文字，优先保持源角色可见。重复返回只处理当前可见的那一层 |
| 关闭与系统返回 | 按下文的角色表历史层契约接入 `useBackLayer`。Escape 或系统返回先从详情回列表，再从列表关闭。显式关闭清空选择和列表位置。使用关闭原因决定焦点归属 |
| 投票、待办和普通公开消息 | 阅读态继续复用 `NominationNotice`、`PrivateActionNotice` 和普通公开轻通知。现有举手、不举手、鬼票确认和计票截止按同一时钟执行。新提醒不夺阅读焦点。用户点提醒里的「返回城镇」时关闭整卡并沿用现有定位本轮表决或处理待办的流程。此路径由目标界面接管焦点 |
| 处决、终局 | `GuidePriorityBoundary` 命中同局当前未看的关键事件后，卡片 `hidden + inert`，注销自身返回层及键盘监听，保留列表和详情 DOM。现有投票提示及其确认层让位，`EventStage` 消费原时序与完成/跳过信号。结束后显示返回条，包含「返回角色表」及「继续城镇」或「查看结算」。点返回恢复原详情或列表、滚动与焦点。点退出彻底关闭并交出焦点 |
| 隐私遮盖、切后台、换房/账号/新局 | 复用玩家隐私遮盖和账号切换入口。速查卡可见或挂起时，遮盖或 `visibilitychange` 进入后台都关闭整卡，放弃返回提示与焦点恢复。换组作用域时同步卸载。随后回前台或响应晚到时保留现有城镇恢复、隐私幕与同步顺序 |
| 断线、刷新、异步异常 | 同一作用域内的普通快照刷新和重连保留正在浏览的角色与位置。页面刷新后按现有房间恢复逻辑重进，卡片从关闭开始。图标加载失败保持 32px 占位。规则文字与图标、立绘载入互不等待。房间请求、投票请求和服务端错误沿用现有处理方式 |

列表持续挂载，详情是同一卡片的兄弟面板，各自有正文滚动容器。隐藏面板用 `hidden + inert` 保留 DOM 与滚动状态，任一时刻只有一个正文可见且可滚动。列表恢复顺序为 DOM 提交、恢复滚动、再聚焦。详情也在 DOM 提交后聚焦其标题。

速查卡请求区分「正在阅读」与「等待显式返回」。`PlayerGame` 通过 App 传递的速查请求标记和 `useGuidePriority()` 判断实际阅读态。挂起时让出底层界面，只有当前场景本身需要时才显示提名提醒。角色表入口在请求仍挂起时禁用。手册原有 `guideOpen` 行为继续服务其原入口。

### 浏览器返回和关闭原因

- 列表与详情使用 `useBackLayer` 的可选角色表组。卡片可见时注册列表层，再在详情注册子层，系统返回和 Escape 仍由最高已注册层消费。系统返回已经移动历史指针，卸载该层时根据当前 `ravensLayer` 判断是否还需要程序化回退。未传角色表组的调用沿用原行为。
- 角色表组释放当前层时，由 `useBackLayer` 的模块级 capture 处理程序化回退。记录失效角色层 ID、清理前的 URL 和 `ravensScreen`，每次只调用一次 `history.back()`。到达另一个已失效角色层时消费该事件并继续回退。到达同 URL、同 `ravensScreen` 的有效父层或玩家页基线时消费最后一次事件并解除等待。该事件不送给 App 的页级处理器，免得清空正在提交的 `busy` 或改动 `entryEpoch`。如果确认层仍在角色层上面，先由确认层拥有返回，等回到失效角色层时再由公共 capture 继续清理。系统导航抵达不同页或 URL 时终止这组清理并交给原处理器。
- 程序化回退期间最多记录一个打开或恢复意图。回退完成后重新校验页面、作用域、阶段与遮盖状态，再登记新历史层。详情返回导致的短暂回退期间，角色行可保持可见，新的详情请求同样等待回退结束后登记。切后台、遮盖、换房、新局或正式页面导航清除待执行意图。
- App 用同一内部关闭函数接收 `dismiss | town-action | scene-dismiss | discard`。关闭按钮、系统返回和列表 Escape 为 `dismiss`，正常复焦到原触发点。点当前提醒处理行动或表决为 `town-action`，等待城镇渲染后聚焦对应的本轮表决入口、确认首夜信息或当前夜间行动入口。若对应动作在这期间已处理，聚焦城镇导航。返回条选择继续城镇或查看结算为 `scene-dismiss`，聚焦城镇导航或结算标题。遮盖、后台和作用域更换为 `discard`，丢弃旧触发点。终局中无原触发点时，普通关闭也聚焦结算标题，给标题提供 `tabindex="-1"` 的聚焦入口。

### 通知与焦点接线

- 速查卡可见背景沿用 `guide-host`、可见 `guide-backdrop` 与现有投票避让。带表决提醒时，继承 `--nomination-notice-height` 的实际占位。卡片可见时用专用类限制投票浮层最大高度，扣除安全区及 136px 卡片空间后计算浮层高度上限，浮层内容可独立纵滚，计票和举手按钮仍可达。`ResizeObserver` 使用限高后的实际高度向卡片回传占位。待办走既有安全区预留。通知与卡片各自拥有滚动区，卡片正文只有一个可见滚动区。卡片挂起时移除可见 `.guide-backdrop`，归还城镇可操作性。
- `PrivateSceneStage` 新增可选 `suppressInbox`。速查卡一整个会话内停用「查看/继续演出」浮层和已有重播提示的操作位。可见时令现有 `reading=true` 保持私密自动演出入队等待，挂起时继续复用 `covered=true`，退出后由原队列决定续播。此输入只影响阅读期间入口展示，已授权的队列、回执、动作确认和已有重播状态仍由原私密演出处理。
- `PlayerGame` 在速查卡可见时将底层 `.player-private` 设为 inert，保持原隐私幕的 hidden 条件。投票、待办和确认框仍位于底层容器外。Tab 顺序包括卡片与当时可用的提示按钮，跳过不可见、inert 和禁用控件。打开鬼票或枪击确认时由已有 `RoomSheet` 接管键盘。关闭确认框后恢复原按钮焦点与阅读位置。屏幕阅读器可抵达提示区且不会读到被遮盖的底层控件。
- 标题、分类、角色行和详情都有可见键盘焦点。分类跳转用按钮和真实分组标题，角色行以可见名称作为可访问名称，以摘要作为描述。图标用空 `alt`，防止角色名字重复朗读。尊重 `prefers-reduced-motion`，阅读切换即时完成。

## 4. 原创角色图标

图标沿用鸦钟夜话的暗铜色调。每枚以一个大轮廓为主，配一个能在小尺寸保留的结构或负形。共用铜金主面 `#DDBD83`、暗面 `#785635` 和高光 `#F1D9A3`。暗面只做内侧刻痕，决定轮廓的外沿保持明亮。允许猩红披风用暗红里衬，分类仍以标题和文字识别。图标在同一个 `#1C1813` 深色底座上评审，底座由组件绘制。四类可以沿用现有标题色，图标之间的区分依赖形状。

设计工作幅为 96×96 比例。主体占约 76×76，保留约 10px 透明安全边，主体光学居中。任何承载辨认的线段或负形在 96px 版至少 6px，保证缩到 32px 仍约 2px。拐角允许细小高光，舍弃细密纹理、文字、数字和通用套框。所有形状重新绘制，使用项目内现有立绘、道具与名称作概念参考。

## 5. 权限、兼容与配置

前端随包提供公开目录和美术资源。速查组件既不持有 `PrivateView`，也不获取角色分配、线索、实际阵营、透视标记或本局在场角色。本人身份、魔典、投屏头像、投票许可与结果继续使用原数据边界。房间选项「6人邪恶协作」仍由原菜单展示。卡片读取角色公开能力与规则细节，范围不包含会随房间配置变化的开局说明。

角色表行为在客户端内存完成。`HTTP/WS`、协议 7、快照 5、公开演出时序 4、浏览器持久化结构和数据库无需迁移。新增资源用独立 `role-icons-v1/` 地址，后续美术更新按版本建目录。打包包含 22 张运行图。沿用当前 Web 构建与环境配置，使用已有 `sharp` 依赖，功能无需开关。旧进行中房间随前端更新可直接读取同一角色目录。若发现线上阻断，按现有发布流程回退这次前端变更并保留房间进度。发布需独立授权。
